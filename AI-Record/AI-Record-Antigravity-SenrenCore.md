## 一、 项目背景与硬件环境摸排

### 1. 词典笔硬件基础与运行约束
在项目启动初期，通过 ADB 命令行对有道词典笔 X6 Pro 的底层系统环境进行了全面检测：
1. **处理器与内存**：
   - 核心 SoC 为瑞芯微 RK3562（4 核 ARM Cortex-A53 @ 1.8GHz），搭配 Mali-G52 GPU（但官方 Wayland 栈未开放 OpenGL ES 加速，纯靠 CPU 软绘与 2D 硬件 blit）；
   - RAM 总量约为 1GB，系统后台驻留有 `guardian`、`runDictPen`、`runResourceManager` 等系统服务，留给第三方小程序的空闲常驻内存约为 150MB~200MB；
   - 存储空间方面，内部 eMMC 挂载的 `/userdisk` 分区有约 42GB 的可用存储空间，足以存放经过合理格式化的高保真音频与图像资产。
2. **显示系统与分辨率**：
   - 显示服务基于 Weston Wayland 构建（无 X11），单一全屏应用顶层渲染；
   - 屏幕物理分辨率为 **960 × 266 像素**，长宽比达到极端的 **3.61 : 1**（超宽带鱼屏）；
   - 词典笔前端运行时（基于 QuickJS + Falcon 框架）将逻辑视口标准化为 **800 × 220 像素**。
3. **音频输出瓶颈**：
   - 系统音频采用 ALSA 底层驱动，官方默认配置为**独占模式**，不支持原生硬件多流混音；
   - 若直接通过多进程或调用多个独立播放管道同时打开声音设备，会导致设备忙（Device or resource busy）冲突，从而引发无声或引擎崩溃。

## 二、 游戏资源逆向分析与解包工具链研发

### 1. PC Steam 原版资源加密逆向探索
最初针对用户电脑中的 PC Steam 官方中文版目录（`/Volumes/500GB/千恋万花/(無修正ゲーム) Senren Banka Steam Edition`）展开技术分析：
- **封包结构（XP3）**：
  - 文件头具备标准 `XP3\r\n \n\x1a\x8bg\x01` 签名，但索引区包含柚子社专属的 `sen:` 二级散列映射表；
  - 运行时依赖 Windows 专有插件 `plugin/PackinOne.dll`，内部注册了 `BasicCryptFilter<BlockStreamCipher<ChaCha@DJBernsteinStreamCipher>>` 流密码，对数据段执行动态混淆。
- **内部数据格式**：
  - 剧本采用编译后的 PSB 字节码（`.ks.scn`），图片多为带有五官差分图层的 TLG 压缩格式（`.pimg` / `.tlg`）。
- **工具链验证**：
  - 发现游戏目录附带的去码补丁（`unencrypted/`）包含 50 组明文 `.pimg`；
  - 在 macOS 环境下配置了 Mono 运行环境，调用 FreeMote 工具链的 `PsbDecompile.exe` 对 `.pimg` 进行结构解析；
  - 自行编写并编译了 C++ 图像转换程序 `tlg2bmp`，成功打通了从去码事件 CG 到 1080p 无修正 PNG 图像的无损还原流水线。

### 2. 移动端无加密资源的全自动化解包与分类
为了彻底规避专有 Windows DLL 的流密码解密开销，项目转向分析并采用了适用于移动端模拟器的无加密移植版本（`v3_城彩学园_官中_千恋万花`）：
- **存储保护约束**：
  - 当时本地 Mac 硬盘剩余可用空间不足 6GB，若写入临时文件将引发磁盘写满故障；
  - 研发的所有解压脚本、缓存目录与转换产物严格限定在外部 500GB 硬盘（`/Volumes/500GB/`），确保零本地磁盘占用。
- **解包器开发（`unpack_all.py`）**：
  - 编写了纯 Python 实现的原生 XP3 递归解析工具，自动处理索引偏移重定向与二级 zlib 解压缩；
  - 批量提取 `data.xp3`（39,045 个文件）与 `adult.xp3`（878 个文件），总计解包并分类整理了 **39,923 个独立素材文件**；
  - 分类成果：
    - `audio/voice/`：35,268 条角色剧情独立配音（OGG 格式）；
    - `audio/bgm/`：全套原版背景音乐（OPUS 格式）；
    - `audio/se/`：系统音效与场景环境音；
    - `characters/`：按角色名分类的立绘素体与表情差分层（芳乃、茉子、丛雨、蕾娜、小春、芦花等）；
    - `scenario/`：全量剧本字节码与配置文件；
    - `ui/`：界面切片、按钮与系统提示素材。

## 三、 原版 UI 逆向解析与超宽屏适配规范制定

为确保移植后的视觉小说界面并非主观凭空臆测，而是精准复刻原版艺术风格，对官方中文版界面包（`uipsd/cn/`）进行了反编译逆向分析，提取各界面的实际图层坐标：

1. **原版真实图层数据提取**：
   - **主游玩窗口（`window_cn.json`）**：底图位于 `top: 817, height: 263`，姓名标签框位于 `(450, 830)`，正文对话区位于 `(468, 875)`，点击等待光标位于 `(1561, 969)`；
   - **标题主菜单（`title_cn.json`）**：LOGO 位于 `(33, 60)`，左侧纵向排布 8 个毛笔风格功能按键（`:defo` 常规、`:over` 聚焦、`:on` 按下）；
   - **存读档系统（`sl_save_cn.json`）**：原版采用 4 列 × 4 行共 16 槽位分页网格，每槽位包含 224×126 的 16:9 现场缩略图、章节标识与台词摘要。
2. **规范文档编制（`UI_SPECIFICATION.md`）**：
   - 针对 3.61:1 的带鱼屏，正式制定并输出了**「三分栏」布局规范**：
     - **左侧 16:9 舞台区（390 × 220 像素）**：无遮挡完整呈现背景、角色立绘与名场面 CG；
     - **中间大字剧情区（320 × 220 像素）**：采用半透明墨黑底板，20~22px 大字号显示台词，支持长文本触摸平滑滚动；
     - **右侧触控操作栏（90 × 220 像素）**：纵向放置大尺寸按键（语音重听、快进/自动、历史履历、存读档、设置菜单）。

## 四、 核心引擎架构改造与原生混音插件

### 1. 多声道 PCM 软件混音动态库（`libjsapi_gal.so`）
为了突破 RK3562 单通道 ALSA 声卡限制，编写了专属的原生 C 语言插件源码（`native/gal_gs.c`），并交叉编译为 aarch64 动态库：
- **混音架构**：
  - 启动常驻高优先级音频工作线程，持续向底层 ALSA 输出单一合成后的 PCM 音频流；
  - 维护两条独立的内部逻辑音轨：
    - **Track 0 (BGM)**：负责背景音乐的无缝循环播放、分级音量增益与淡入淡出调节；
    - **Track 1 (Voice)**：负责角色台词配音的一次回放，具备即时切断、同角色打断与自动降低背景音（Ducking）能力；
- **QuickJS 绑定接口**：
  - 向上层 JavaScript 暴露 `playBGM(path)`、`playVoice(path)`、`stopVoice()`、`setBGMVolume(vol)` 等原子方法，彻底消除了音画脱节与声卡死锁。

### 2. 小程序前端与真机构建系统
- **样式与视口校验（`build.py`）**：
  - 自动编译处理各页面的 CSS 样式，并强制校验所有图层的 `top + height <= 220px`、`left + width <= 800px` 物理约束，杜绝越界变形；
- **真机联调验证**：
  - 使用 ADB 授权连接词典笔（授权口令：`ydpen2026`），通过 `miniapp_cli` 自动打包并安装 `.amr` 应用；
  - 利用 Wayland Framebuffer 抓屏机制导出实际运行效果，反复调整立绘层级、对话滚动顺滑度与存档数据持久化。
